# 第 18-19 集：性能分析——执行频次与慢查询日志

> 课程来源：黑马程序员《MySQL数据库入门到精通》进阶篇 · 第 18 集（查看执行频次）+ 第 19 集（慢查询日志）
> 主题：优化前的两步侦察——先看数据库是读多还是写多，再从查询中揪出慢的那几条
> 所有语句均在 MariaDB 中实际运行验证，报错与踩坑为真实终端记录

---

## 一、性能分析的四步路线图

| 步骤 | 手段 | 回答的问题 |
|---|---|---|
| ① 执行频次 | `SHOW GLOBAL STATUS LIKE 'Com_%'` | 数据库是读多还是写多？该往哪个方向优化？ |
| ② 慢查询日志 | `slow_query_log` | 哪些 SQL 是慢的？ |
| ③ profile | `SHOW PROFILES` | 一条慢 SQL 的时间花在哪个阶段？ |
| ④ EXPLAIN | `EXPLAIN SELECT ...` | 这条 SQL 的执行计划是什么？索引用了吗？ |

先定性（读/写比例），再定位（慢 SQL），再剖析（时间分布），最后开方（执行计划）。

## 二、查看执行频次（第 18 集）

### 2.1 核心命令

```sql
-- 一次纵览四个核心计数器
SHOW GLOBAL STATUS LIKE 'Com______';

-- 全列出（170+ 行，不怕数错下划线）
SHOW GLOBAL STATUS LIKE 'Com_%';

-- 精确查单个（日常推荐）
SHOW GLOBAL STATUS LIKE 'Com_select';
```

**关键认知（实测得出）**：`LIKE` 中下划线 `_` 匹配**一个字符**，所以下划线数量 = 命令名字母数：

| 状态变量 | Com_ 后字母数 | 需要的下划线数 |
|---|---|---|
| Com_select / insert / update / delete | 6 | **6** |
| Com_begin / check / flush / grant / purge / reset | 5 | 5 |
| Com_help / kill / load | 4 | 4 |

> 实测教训：下划线数不对，匹配到的就是"别的命令"（4 条下划线返回 Com_help/Com_kill/Com_load），甚至 Empty set。**数不准就直接查全名或用 `Com_%`。**

### 2.2 三种作用域

```sql
SHOW GLOBAL STATUS LIKE 'Com______';   -- 服务器启动以来的累计值（判断负载用这个）
SHOW SESSION STATUS LIKE 'Com______';  -- 当前连接的计数
SHOW STATUS LIKE 'Com______';          -- 不写默认 SESSION
```

**实测对照**：

```
global  Com_select = 131    -- 服务器累计
session Com_select = 2      -- 当前连接只执行了 2 条
```

同一名词差 65 倍——**判断业务负载必须用 GLOBAL**。

### 2.3 本库读数结论

```
Com_select = 131    Com_insert = 7    Com_update = 1    Com_delete = 1
```

**读多写少（查询占比约 93%）→ 优化重心在查询侧：加索引、消灭慢查询。**

### 2.4 GLOBAL 计数器 = 服务器的"操作史"对账

从 `Com_%` 的 170 行输出中，非零计数器逐一对上了学习轨迹：

| 计数器 | 值 | 对应操作 |
|---|---|---|
| `Com_create_db` | 1 | 创建 demo 库 |
| `Com_change_db` | 3 | USE demo 执行 3 次 |
| `Com_create_user` / `Com_grant` / `Com_flush` | 各 1 | 搭远程环境：建用户、授权、刷新权限 |
| `Com_create_table` / `Com_drop_table` | 2 / 1 | 建过 2 张表、删过 1 张 |
| `Com_create_index` / `Com_drop_index` | 5 / 4 | 索引实验建 5 删 4，账面平衡 |
| `Com_show_keys` | 5 | SHOW INDEX 执行 5 次 |

**结论**：计数器可用来"对账"——生产上排查"谁建了/删了索引"就是这么查的。

### 2.5 两个隐藏细节

**① SHOW 类语句不污染 Com_select**

```
Com_show_status = 14    -- SHOW STATUS 类语句有独立计数器
Com_select = 131        -- 重复查询期间稳定不动
```

各归各账：`SHOW INDEX` 计入 `Com_show_keys`，`SHOW VARIABLES` 计入 `Com_show_variables`。

**② LIKE 默认不区分大小写**

`Com_%` 的输出末尾混进了 `Compression | OFF`——因为它同样匹配 `com_%`。要区分大小写需 `LIKE BINARY 'Com_%'`。

## 三、慢查询日志（第 19 集）

### 3.1 涉及的参数

| 参数 | 默认值 | 含义 |
|---|---|---|
| `slow_query_log` | OFF | 慢查询日志开关 |
| `slow_query_log_file` | 主机名-slow.log | 日志文件路径（建议写绝对路径） |
| `long_query_time` | 10.000000 | 慢查询阈值（秒），超过则记录 |

开启前实测确认：

```
slow_query_log      = OFF
slow_query_log_file = archlinux-slow.log
long_query_time     = 10.000000
```

### 3.2 开启方式一：运行时（临时，重启失效）

```sql
SET GLOBAL slow_query_log = ON;
SET GLOBAL long_query_time = 2;
```

⚠️ **注意权限**：`SET GLOBAL` 需要 SUPER 权限，普通业务账号会报错：

```
ERROR 1227 (42000): Access denied; you need (at least one of) the SUPER privilege(s)
```

解决：切服务器 root 走本地 socket（Arch 默认 root@localhost 用 unix_socket 认证，免密）：

```bash
sudo mariadb        # 在虚拟机本机终端执行
```

### 3.3 开启方式二：配置文件（永久，推荐）

视频里改 Windows 的 `my.ini`；**Arch + MariaDB 的对应位置**：

```bash
sudo vim /etc/my.cnf.d/server.cnf
```

在 `[mysqld]` 段下追加：

```ini
[mysqld]
# 慢查询日志
slow_query_log = ON
slow_query_log_file = /var/lib/mysql/archlinux-slow.log
long_query_time = 2
```

```bash
sudo systemctl restart mariadb
```

> **路径教训**：默认值 `archlinux-slow.log` 是相对路径，实际落在数据目录 `/var/lib/mysql/`（属主 mysql:mysql，权限 660）。配置里写**绝对路径**避免歧义。

### 3.4 实测踩坑：SET GLOBAL 后会话仍显示旧值

现象：

```sql
set global long_query_time = 2;          -- Query OK
show variables like 'long_query_time';   -- 还是 10.000000 ！
```

原因：**`SHOW VARIABLES` 默认显示会话级值**，会话值是连接建立时从全局继承的快照，之后全局修改不影响已存在的连接。`slow_query_log` 没有此问题——它只有 GLOBAL 作用域（日志开关是服务器级），SET GLOBAL 当场生效。

验证方法：

```sql
SHOW GLOBAL VARIABLES LIKE 'long_query_time';   -- 明确看全局值：2.000000
SET long_query_time = 2;                        -- 或让当前会话立即生效
```

### 3.5 选做参数：记录未走索引的 SQL

```sql
SET GLOBAL log_queries_not_using_indexes = ON;
```

**学习阶段不建议开**：小表（25 行）上优化器判断全表扫描比走索引便宜是正确行为，开了会刷满日志干扰判断。

## 四、抓捕实验

```sql
-- 准备：会话级阈值同步（避免快照问题）
SET long_query_time = 2;

-- ① 快查询：1 秒 < 2 秒阈值，不应被抓
SELECT SLEEP(1);

-- ② 慢查询：4 秒 > 2 秒阈值，应被抓
SELECT SLEEP(4);

-- ③ 普通查询，不应被抓
SELECT * FROM tb_user;
```

查看日志（在虚拟机 shell 上）：

```bash
sudo cat /var/lib/mysql/archlinux-slow.log
```

日志单条记录格式：

```
# Time: 241101 10:23:45
# User@Host: root[root] @ localhost []
# Thread_id: 12  Schema: demo
# Query_time: 4.000123  Lock_time: 0.000000  Rows_sent: 1  Rows_examined: 0
SET timestamp=1730439825;
SELECT SLEEP(4);
```

**关键字段**：

| 字段 | 含义 |
|---|---|
| `Query_time` | 执行耗时（判断"慢"的直接依据） |
| `Lock_time` | 等锁时间 |
| `Rows_sent` | 返回给客户端的行数 |
| `Rows_examined` | 实际扫描的行数——**和 EXPLAIN 的 rows 列同一血统，判断"是否暴力扫描"的关键** |

预期结果：SLEEP(4) 入日志，SLEEP(1) 与 tb_user 查询不入。

## 五、MariaDB 加分项：慢日志可当表查

MariaDB 支持 `log_output` 切换输出目标，MySQL 没有这么灵活：

```sql
SHOW VARIABLES LIKE 'log_output';    -- 默认 FILE

-- 改为 TABLE 后，慢 SQL 直接是表数据：
SET GLOBAL log_output = 'TABLE';
SELECT start_time, user_host, query_time, sql_text
FROM mysql.slow_log
ORDER BY start_time DESC;
```

两者可同时开（`FILE,TABLE`）。日常排查用 TABLE 模式可以直接写 SQL 分析慢日志，很方便。

## 六、完整操作脚本（可直接执行）

```bash
# ============ 虚拟机 shell ============
# 1. 临时开启（免密 root socket 连接）
sudo mariadb
```

```sql
-- ============ MariaDB 内 ============
SET GLOBAL slow_query_log = ON;
SET GLOBAL long_query_time = 2;
SET long_query_time = 2;                          -- 会话级同步
SHOW VARIABLES LIKE 'slow_query_log%';            -- 确认 ON
SHOW GLOBAL VARIABLES LIKE 'long_query_time';     -- 确认 2.000000

-- 抓捕实验
SELECT SLEEP(1);
SELECT SLEEP(4);
SELECT * FROM demo.tb_user;
exit;
```

```bash
# ============ 回到 shell ============
# 2. 查看日志
sudo cat /var/lib/mysql/archlinux-slow.log

# 3. 永久化：改配置 + 重启
sudo vim /etc/my.cnf.d/server.cnf        # [mysqld] 段加三行（见 3.3）
sudo systemctl restart mariadb
sudo mariadb
```

```sql
-- 4. 重启后确认配置文件生效
SHOW VARIABLES LIKE 'slow_query_log%';
SHOW GLOBAL VARIABLES LIKE 'long_query_time';
```

## 七、环境运维附录：开启 SSH 远程管理

过程中发现虚拟机 22 端口未监听（Windows 侧 `ssh` 报 `Connection refused`），顺手修复：

```bash
pacman -S openssh
systemctl enable --now sshd
ss -tlnp | grep 22      # 确认 0.0.0.0:22 在监听
```

之后 Windows 可直接 `ssh cxk@192.168.31.200` 管理虚拟机，不必坐到虚拟机终端前。

## 八、常见错误与避坑（全部实测踩过）

| 报错/现象 | 原因 | 解法 |
|---|---|---|
| `Unknown system variable 'show_query_log'` | `slow` 拼成 `show`，且 SHOW VARIABLES 同样拼错返回 Empty set | 见到 Unknown system variable 先查拼写 |
| `ERROR 1227: Access denied ... SUPER privilege` | 普通用户执行 `SET GLOBAL` | `sudo mariadb` 切 root socket 连接执行 |
| `SET GLOBAL long_query_time=2` 后会话仍显示 10 | SHOW VARIABLES 显示会话快照，全局修改不影响已有连接 | `SHOW GLOBAL VARIABLES` 验证，或 `SET long_query_time=2` 同步会话 |
| `LIKE 'com____'` 返回 Empty set / 匹配到 Com_help | 下划线数 ≠ 字母数（需 6 条匹配 select/insert/update/delete） | 直接查全名或用 `'Com_%'` |
| `Com_%` 输出混入 `Compression` | LIKE 默认不区分大小写 | 严格过滤用 `LIKE BINARY 'Com_%'` |
| 重复查 Com_select 数值不动 | SHOW 语句计入 Com_show_status 等独立计数器 | 正常现象，各归各账 |
| 找不到慢日志文件 | 默认文件名是相对路径 | 用绝对路径配置 `slow_query_log_file`，或 `find /var/lib/mysql -name "*slow*"` |
| SET GLOBAL 重启后失效 | 运行时修改不持久 | 写入 `/etc/my.cnf.d/server.cnf` + `systemctl restart mariadb` |
